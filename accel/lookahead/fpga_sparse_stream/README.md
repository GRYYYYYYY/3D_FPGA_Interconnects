# SPARSE_STREAMED_ALT_V2

This is the **8-lane, 8-owner, Q=1** executable prototype, based on `fe659f008fc58c913bb1c0232d9898caf79fd524`. It is not a 64-owner implementation. The experiment contract is frozen in `config/`; the final evidence report is `docs/lookahead_fpga_sparse_stream.md` at the repository root.

The RTL supports at most 4096 nodes, 64 output cells per sample, 64 samples per batch and 16 runtime cost pairs. A bank has 512 nodes, 1024 physical bucket members, 512 changed IDs, 512 closed IDs and 16 concurrent commit reads. Each frontend has four parent contexts. Each owner has a 4-way × 32-set × 32-byte cache, 32 MSHRs, 16 dirty slots and 64-entry request/response FIFOs; the router also has eight separate 64-entry owner queues. Directory keys cover 4096 buckets. The parent stream and finite contexts replace a materialized unbounded active list.

`reference.cpp` is the prepared-CSR functional implementation and independent changed-set oracle. Its large-graph member pool and each active/changed/closed list are separately bounded to 524288 entries. Its touched oracle is bounded by N and is verification-only. Eight/64-bank occupancy audits do not instantiate large hardware. `owner_model.hpp`, `owner_f0_model.hpp` and `tile_model.hpp` are handwritten cycle models with explicit finite state, queues, RAM latency and arbitration; they do not invoke RTL or consume golden frontiers. The memory driver and correctness checker are shared between RTL and model, so the checks are not independent testbench implementations. XSim supplies a separate memory schedule.

The host supplies immutable input data, source and target counts. All samples’ cell/type metadata is preloaded before reset; the 4096-pair finite output array retains all samples until a single final readback. The `output_index` port is 12 bits, with index `sample*64+cell`. Golden output is used only for complete output comparison. Within a batch, cost preload occurs once and all per-sample initialization, internal memory, commit and draining are counted. Final testbench output readback is separately counted and excluded from `resident_cycles`. A new graph/batch requires reset. At the tile boundary the finite, preloaded job command service is assumed to supply one start handshake per sample, counted as one cycle; the outer producer is not included in tile OOC, and this is not measured per-sample PCIe host dispatch. The admission wrapper must reject out-of-range node/cell/cost formats before truncating hardware ports. `done && !error` is the success condition; a sticky error requires discarding the entire output and resetting. Overflow tests publish no output map.

From the worktree root, using g++ and Verilator 4.038 (the recorded local installation is the default in `sim/build.py`; other installations can set `SPARSE_VERILATOR` and `VERILATOR_ROOT`):

```bash
g++ -O3 -std=c++17 -ffp-contract=off -Iaccel/lookahead/include -Iaccel/lookahead/round6_1 accel/lookahead/fpga_sparse_stream/reference.cpp -o /tmp/sparse_reference
# Run once per entry of fpga_sim_restart/config/inputs.json:
# /tmp/sparse_reference WORKLOAD ORIGINAL_ALT_OUTPUT RESULTS_DIR
# This writes prepared.bin, full output.bin, per-wave work and capacity.json.

python3 accel/lookahead/fpga_sparse_stream/sim/build.py batch_f1
python3 accel/lookahead/fpga_sparse_stream/sim/build_model.py batch_f1
python3 accel/lookahead/fpga_sparse_stream/sim/calibrate.py --variant batch_f1 --latency 60

python3 accel/lookahead/fpga_sparse_stream/sim/build.py f0_batch
python3 accel/lookahead/fpga_sparse_stream/sim/build_model.py f0_batch
python3 accel/lookahead/fpga_sparse_stream/sim/calibrate.py --variant f0_batch --latency 60
```

`calibrate.py` also takes `--case` and multiple `--latency` values. The default includes `stress`, whose inputs are generated by `sim/make_stress.py`; `--randomized` generates `stress_random`. Build `sim/oracle.cpp` with the reference include paths to generate their original ALT outputs, then run the functional reference into `stress[/_random]/functional`. The source generators preserve eligible skip/break cases, same-bucket reentry, repeated destinations and missing target output. The historical native workload paths and golden paths are read-only dependencies, recorded in receipts. No GPU job is launched.

The finite memory driver has **25 shared read/write services**, allocated as eight owner, eight frontend, eight initialization/commit, and one cost/closure service, out of the assumed 32-channel envelope. Each service allows 64 outstanding 32-byte transactions with a two-cycle issue gap, deterministic random backpressure, out-of-order responses, and writes visible only at ACK. Nominal aggregate port capacity at an *assumed* 200 MHz is at most 80 GB/s for these 25 services. Latencies 16/60/120 cycles plus 0–6 cycles jitter correspond to 80/300/600 ns plus 0–30 ns at that assumption. These are not HBM measurements. The 64-owner physical-channel mapping and large graph storage are not implemented.

`python3 accel/lookahead/fpga_sparse_stream/sim/test_owner_changed.py NEW_RUN_DIR` reproduces the owner/changed-queue composition test with 768 owner-local lines and delayed commit acknowledgements. Its CAP4096 changed queue forces cache evictions; it is semantic component coverage, not the CAP512 tile calibration. The original run is `owner_changed_eviction`.

Dynamic capacity regressions use `sim/build.py NAME -GMEMBER_CAP=2`, `-GCHANGED_LIMIT=2`, or `-GCLOSED_LIMIT=2`, then `sim/run_small.py 60 NAME expected_rejection`. A nonzero exit with DUT error and no `output.bin` is the expected result. Keep each attempt in a different directory.

For Vivado 2022.2, `sim/ooc.tcl SRC_ROOT OUTPUT_DIR sparse_tile` runs synthesis through route for U280, with a 5 ns clock and explicit input/output delays. Use the absolute executable and process-local `LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libudev.so.1` on this host. The recorded flow uses `taskset -c 0-7` and maxThreads=8. One implementation process is run at a time. This is shell-free OOC, not a board clock qualification. `sim/tile_tb.sv` is the XSim full-d3 checker; generate memory/config/expected files with `sim/export_xsim.py` and run the simulator from that directory. The test uses literal `$readmemh` filenames, a bounded watchdog and explicit `XSIM_TILE_PASS` rather than process exit code alone.

`analyze.py` checks output hashes and every wave's commit count and summarizes throughput/traffic. `optimistic_bound.py` derives a necessary bound from **new** complete BNN/LSTM work and structural minimum service intervals. It does not produce a large architecture simulation prediction. It deliberately omits commit/init/memory/drain; at 200 MHz even that bound exceeds the retained compact CUDA reference. This invokes contract P3's stop on scaling the fixed structure. No old calibration or unsupported full-kernel clock is inherited. All physical and full-large-model limitations are recorded in the report and evidence state.

The final routed tile uses 243739 LUTs (39776 LUTRAM), 75203 FFs, 168 RAMB36 and 32 RAMB18. At the 5 ns target, setup WNS is -7.035 ns and hold WHS is -0.048 ns. Routing completed, but 200 MHz is not qualified. `physical_audit.py` extracts the terminal reports; `sim/run_postroute.py` reopens the checkpoint read-only and checks that its hash is unchanged. These reports do not qualify a shell, board, or full 64-owner design.

## Initial implementation review

The six-stage elastic arithmetic requires six occupied registers per lane and
real backpressure propagation. A new `due` constant in the old two-slot queue is
insufficient. E/beat state can be released when immutable operands are captured,
but freed nonelastic slots are unavailable for admission on that same edge.

The backend context's FIFO2 boundaries and deferred directory/completion ACKs
must be included or explicitly replaced by identical stages of the common
network. Merely adding a latency constant omits capacity and handshake behavior.
The old local four clients and the common global four classes are different
topologies; local calibration cannot be silently transferred between them.

The initial `df_rr_router` used a rotated linear priority scan. The services owner
was asked to implement balanced hierarchical selection and payload routing, or
an explicitly staged alternative with matching model timing. One C++ loop over
all clients is not physical proof. Final resolution belongs to actual source
and calibration receipts, not this initial review note.

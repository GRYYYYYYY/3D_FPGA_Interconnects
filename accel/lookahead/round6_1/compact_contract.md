# R6.1 software and bounded candidate contract

Base: `480ba6d5cc2b9d73696a44315777c0e658d8a7b4`. The existing STRICT and R6 files are unchanged. This directory implements ALT_BUCKET_FP32_V1, not STRICT equivalence. Only shifts 0 and 20 are admitted; the direct directory and live CUDA qualification use shift 20.

## COMPACT_RRG_V1

The original CSR row offsets remain uint64. Every original edge remains in the same position; its destination is uint32 and its unused switch identifier is omitted. No static filtering, sorting or graph-specific constants are introduced. A node is uint16: type bits [1:0], interposer bit [2], segment+1 bits [4:3], cost index bits [15:5]. Admission requires type 0..2, inter 0..1, segment -1..1 and cost index <2048 and <cost_count. Invalid values fail before output publication. All endpoints and CSR bounds are validated. Both cost FP32 words, jobs, source identities, per-qid mapping, targets and eligibility/SINK rules are unchanged. Values remain finite positive normal or +0 under the existing ALT admission; unsupported numerical results fail. No quantization, fast math or fused addition is enabled.

CPU and CUDA use the same pack/decode definitions. The CPU generic search changes only the representation/selected directory. CUDA keeps the R6 initialize/expand/commit/confirm/advance control and whole-pair uint64 atomic minimum. The unmodified R6 CUDA executable is retained as G-basic. A separate original-format reusable-solver control isolates the refactor from compact decoding. Compact conversion and preparation are outside warm E1 and reported independently. The current CLI retains the original host Workload while allocating packed node/edge vectors; host peak memory therefore increases by the packed arrays (BNN166127680 B), even though accessed representation and uploaded device graph shrink. No host peak-memory reduction is claimed. The refactored CUDA solver additionally allocates its host result vector inside E1; unchanged G-basic prepares that buffer before repeated E1. The separate original-format refactor control shares the exact new host allocation scope with compact, isolating representation effects. CUDA live currently uses original format: offline compact validation does not grant compact native qualification.

## Direct directory CPU control

4096 keys, 64 leaf bitmap words and a 64-bit top bitmap per search. The smallest set bit selects the next bucket. Popping moves out the entire frontier vector, then clears the old bitmap bit; commits subsequently append to a new vector and publish its bit. This synchronous phase ordering preserves same-bucket reopening and prevents lost notifications. Candidate generation reads a frozen label snapshot. Whole-pair strict improvement, stale filtering and target completion after closure remain unchanged. The existing finite 4*N+1 queued-member admission is retained; capacity failure publishes no output. This CPU implementation uses bounded-count dynamic vectors, not a claim of physical SRAM layout or FIFO timing.

## Finite proposal/chunk diagnostic family

One selected family: 64 owner banks per qid, `(qid,dst%64)` ownership, whole-pair fully-associative LRU caches with 16/32/64/128 entries per bank considered only in bounded windows. The window set is qid 0 waves 1,10,30,50,59 in original CPU candidate order, capped at 5,000,000 observed candidates per capacity and a 120-second process budget. The CPU search still traverses qid0 to construct real wave snapshots (500M raw-edge/180s internal search ceiling); the 5M cap describes cache observations, not all bootstrap edge traversal. No four-capacity full-batch sweep is performed. Cache lookup is hash based, not a linear scan. Distinct reuse distance is measured within these windows; reference-gap histograms are separate. All-zero distinct-distance arrays in full replay mean **not collected**, not zero reuse distance.

The chosen capacity is the smallest within two percentage points of the 128-entry hit rate. Only it receives one complete tseng and one complete BNN replay. Dirty whole pairs write back on eviction and at every wave barrier. The shadow home state is checked against the actual CPU label array after each full-replay qid completes. In sample-mode rows the legacy boolean `whole_pair_home_equal=true` is a bypass marker (not checked); it is not an equality observation. Only full-mode rows supply that assertion. A selected window begins with the actual wave-start labels. No hit ratio is inferred from whole-wave duplicate counts.

The member model uses one shared 4096-header directory per qid plus sparse `(bucket,bank)` chunk metadata, 32 members per chunk, 16,384 chunks per qid, at most 524,288 members per qid and eight resident qids. Current frontier storage is released only after candidate processing and proposal flush, before commit/publication. It counts member enqueues, pending set writes, chunk publications, empty-to-nonempty transitions and minimum selections separately. A pool overflow fails. The member/chunk pool is shared within a qid; owner tags do not prove that a fixed per-bank SRAM partition fits. Per-owner member high-watermarks and physical allocator/port costs are not measured by this replay. The model does not silently spill or use a CPU fallback.

The memory proposal diagnostic assumes 32-byte transactions and channel `(dst/4)%32` solely to expose modeled channel load. These are not measured HBM transactions or bandwidth. Home arrays and Python/C++ control are software diagnostic state, not an implementable hardware allocation proof. Candidate order is sequential qid then frozen CPU wave/CSR order; it does not simulate concurrent lanes or out-of-order memory responses.

## Explicit model limits and gate

Functional full-batch replay is distinct from a complete finite timed service model. Physical issued/retired timestamps, per-qid concurrent completion timestamps, outstanding-memory limits, real bursts, RAW forwarding latency, bank arbitration, FIFO occupancy/backpressure, pending clears/seen and complete label traffic, reset/output/drain timing, routing/port feasibility and achieved frequency are not supplied by this diagnostic. These fields must remain unknown/not_run in transaction_model.json. No FPGA advantage or service-prototype eligibility follows from a passing functional replay. 125/200 MHz and ideal edge-lane budgets are sensitivities only; unavailable random-RMW bandwidth cannot be replaced with peak sequential bandwidth.

Logical capacity: shared headers 4096*8*16=524288 B; bitmap 4096 B (plus top words); member pool 524288*8*4=16777216 B; sparse chunk metadata 16384*8*32=4194304 B; cache payload/metadata must be counted separately for all 64*8 banks. Headers are not replicated per owner bank. Qid-local label/proposal/pending/seen and cell mappings additionally require external storage and service. Logical counts do not establish placement, ports or finite outstanding requests.

## Timing and qualification

E1 is directly timed reset through full host output and completion synchronization. CUDA resident and readback are nested components, not a replacement for that wall clock. Graph load and preparation are separately recorded; column medians must never be added to synthesize E2. Native CUDA takes current BackendInput pointers, computes every output and uses no reference file. An explicitly enabled diagnostic CPU verification compares every pair on the same live input; capture and verification are excluded from the formal timing cohort. Uncollected native CUDA counters use an explicit unknown sentinel and log marker, not fabricated zero activity. Failure returns nonzero and does not publish a partial map.

R6_1_NATIVE_BUILD_V1 spans entry to exit of MapLookahead::compute, including graph conversion, backend preparation/service, ordered group merge, interpolation, source/OPIN and minimum/interposer lookahead work. RR XML reading and RRG initialization precede this scope and belong to Process; later serialization also belongs to Process. Original VPR uses its equivalent function-scope built-in timer with 0.01-second print precision; the added timer in the private optimized/ALT binary records a direct high-resolution wall interval. LA_LIVE.total_s is a nested subset and is not E2. All formal native arms run as separate processes on the same worker/affinity with fixed inputs and seed; filesystem cache is uncontrolled/shared, not flushed. Timings do not claim cold disk state.

Qualification is per case/backend/shift/representation. Candidate routes must independently read back with unchanged hashes, FULL/STA and zero overuse, and satisfy CPD/wirelength +5% versus paired control. Routing success does not imply STRICT map equivalence. Native qualification of original-format CPU/CUDA cannot be inherited by compact or direct-directory modes.

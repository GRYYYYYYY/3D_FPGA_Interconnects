# 原生 CPU lookahead 切片、存储与有界调度实验

已完成 D0–D3 及布局隔离验证：共 171 项原生样本，171 项合法，171 个 map 与原版串行资格产物逐字节一致。其中正式性能矩阵 120 项，五变体、两电路、4/8 核、重建/缓存、各三次运行重复；诊断样本不进入正式速度比。

**新 bounded 未通过预先冻结的整体选型门槛，继续保留已有组内采样 CPU 主线。** 本轮完成实现与验证，候选默认关闭；局部阶段加速不能替代完整进程和缓存对照。

GEMM 重建时，新 bounded 相对既有组内 CPU 的四核/八核配对进程速度比中位为 0.9861× / 1.0677×。旧 pipeline 八核为 1.0936×，三次范围 1.0891–1.0956；新 bounded 相对它仅 0.9804×（0.9213–1.0014）。本轮支持继续确认已有八核跨组调度，但没有建立新 bounded 相对它的稳定增量。

## 新方法相对已有 pipeline

旧 pipeline 同样使用本轮最终候选二进制，作为正式控制在测量前加入计划。这避免将已有跨组并行的全部收益归于新标量存储、有界组批或切片提交。

| elliptic | 8 | reuse | 0.9906 [0.9832, 1.0742] |

归因边界：frozen→slice 同时含重构与插值重排；slice→compact 是同二进制存储对照；compact→bounded 包含跨组调度、工作区复用/对齐与切片提交的组合。各部分并非都获得了独立性能归因。原插值本身很短，切片重排的主要作用是允许独立提交，不能声称省掉插值计算就产生大幅提速。

## 预先声明的选型规则

GEMM 重建在四核和八核分别要求三次配对进程速度比均大于 1、其中位数大于 1.02；elliptic 与缓存模式要求中位进程退化不超过 2%；所有路线、map 与质量均须通过。门槛未按已见到的正式结果修改。

| 电路 | 核数 | 模式 | 门槛结果 |
|---|---:|---|---|
| gemm | 4 | rebuild | 未通过 |
| gemm | 4 | reuse | 通过 |
| gemm | 8 | rebuild | 通过 |
| gemm | 8 | reuse | 通过 |
| elliptic | 4 | rebuild | 通过 |
| elliptic | 4 | reuse | 未通过 |

elliptic 四核共同缓存的中位时间退化约 3.25%，超过 2% 门槛。缓存路径跳过本轮优化的构建过程，因此不能把这项退化直接归因于 bounded 的 flood 或插值开销。共享资源与其他阶段的波动尚未隔离；按既定规则保留该结果，不剔除或放宽门槛。

## 实现与诊断结论

1. 明确插值只依赖固定 `(from_layer,to_layer,channel,segment)` 二维切片，保留原 x/y 扫描顺序及未采样层默认值。
2. 将仅用于 SMALLEST 代表值的临时单元改为 12 字节标量，保留 occupied 位、严格 `<` 与等值首条目规则。
3. 有界组批限制活跃样本表数量，工作槽私有；最后完成者按原样本顺序归并到首样本表，再提交自己的 source-layer 切片。批间仍有屏障。
4. 未改变原生 flood 起点、堆顺序、图扩展、采样数和最终查询模型；没有新 GPU 接管策略。

D0 没有复现历史约 12 秒重构退步，不能宣布根因已修复。GEMM 同二进制 legacy/refactored/pipeline 顶层 timer 外残差为 42.485/41.676/40.127 秒；XML 与清理仅解释其中一部分。两电路均执行 40 次 flood、36 个不同起点，重复来自跨源层 CHANZ；本轮未实现起点复用。

另外发现并隔离了本轮诊断扰动：五个计数器把工作区扩至 168 字节，相邻槽可能发生缓存行争用。同二进制四核 GEMM 未对齐/对齐诊断调度为 62.951/37.826 秒，计数、map 和路由主体相同。证据支持布局争用，但未采集硬件 cache-to-cache 计数器，不能将这项 1.664× 诊断差值作为未诊断算法收益。详细分项见 [诊断报告](diagnostic_report.md)。

临时预算在正式测量前固定为 2 GiB，单工作区估计 85 MiB，两个电路共用；GEMM 每个标量样本表为 743424 字节。活跃表与工作区对象数量有界，原生优先队列、分配器保留、RR 图及最终 map 不受这一估算硬性封顶。峰值进程内存受 RR XML 读取影响，不能据峰值 RSS 反推临时表上界是否生效。源码公式与限制见 [实现方法](../../docs/native_cpu_slices.md)。

## 适用范围与后续策略

本轮只覆盖两种主电路、固定布局种子的运行重复。原生门槛另覆盖 ex5p 单/双层，三层及以上仍只有前序合成插值验证。比较在相同物理核集合内配对，八个 lane 合计使用 48 个不同物理核，宿主、内存与存储仍共享。cgroup 节流和内存事件覆盖重叠任务，不能把各样本区间差值相加。没有资源独占或统计置信度保证。

已有 CPU 组内采样相对原版的历史收益仍是独立证据；本轮是进一步改进的验证。后续方法选择应同时看 frozen 与 pipeline 对照、完整进程和共同缓存，优先在更多独立电路/布局及隔离资源上确认。本轮不保证论文新颖性，不宣称首创三维寻路、确定性并行或 pipeline 原语。来源与贡献边界见 [查新分析](../../docs/native_lookahead_novelty_analysis.md)。

具体后续顺序：先在隔离资源和留出电路/布局上确认已有八核 pipeline；如继续研究 bounded，再单独捕获八核批次尾部等待和工作区生命周期成本，排除诊断扰动。重复起点复用仍只是未实现候选，需要先验证精确语义，再看完整进程收益。以上是后续建议，本轮没有启动新增实验。

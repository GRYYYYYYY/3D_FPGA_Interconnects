# 原生 lookahead 分项与等价验证

本页只总结已结束的诊断及门槛阶段。正式性能以 confirmation 的完整三重复结果为准。前序共51项原生运行全部合法、map逐字节等价并通过独立FULL/STA。

本轮单次诊断没有复现历史约12秒重构退步，不能将其归因为分配器，也不能宣布历史根因已修复。阶段计时存在嵌套，累计flood时间为线程累计工作，不能与并行墙钟混用。XML及清理解释部分残差，其余主要落在未被原顶层timer覆盖的路由准备/检查及最终分析中。

GEMM三种诊断模式均执行610858906次push/pop、231767280次扩展、2841823840次边访问；elliptic对应15221346、6268560、86534920，工作量完全相同。两电路均40次flood、36个不同起点，重复来自跨源层CHANZ组。本轮没有改变采样次数或加入起点复用。

GEMM原调用的十次插值累计仅0.011138秒，切片重排的主要作用是解除提交顺序限制。按一次未诊断D1四核样本，lookahead占进程16.76%；假设仅该阶段快一倍且其余阶段不变，整进程速度比为1.09147。elliptic对应约1.12%的占比及1.00563的速度比。这只是情景计算。

## 等价与布局隔离

D1覆盖ex5p单/双层、GEMM和elliptic，均为1/4/8核，共12项。GEMM与elliptic三核数路由主体分别一致，CPD/线长为13.2667ns/4095178和10.841ns/97461。D2共16项，存储候选保持同样的map与质量。标量条目夹具100000组、1551076次字段逐位比较零差异，包含NaN、无穷值、正负零和等delay首条目规则。

初版bounded的诊断计数器使工作区变为168字节、8字节对齐。实测机器缓存行为64字节，相邻对象可能产生争用。新二进制以开关隔离原布局和对齐槽；GCC11缺少标准干扰常量，采用128字节fallback、256字节stride。

计数、map、路由主体与CPU集合均相同；另六项小电路及elliptic验证通过，alignment_gate共9项。证据支持热计数器引发/放大的缓存行争用；没有采集硬件cache-to-cache计数器。这个开启诊断的1.664倍阶段差值不是正式算法加速。

临时预算固定2GiB，单工作区按D0最坏观察加保守余量取85MiB，两个电路共用。结果表数量及工作区对象数量有界，优先队列增长、分配器保留空间、最终map和RR图不受这个估算式硬性封顶。

## 正式比较

正式计划在上述诊断后冻结：五变体frozen/slice/compact/pipeline/bounded；GEMM/elliptic；4/8物理核；rebuild/reuse；三重复，共120项。加入同二进制旧pipeline是因为历史重构退步未复现，需要分离已有跨组并行与新方法的作用。同NUMA核组、相同配对CPU集合、缓存模式内交错顺序；宿主和内存仍共享。

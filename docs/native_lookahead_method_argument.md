# 原生 lookahead 并行构建：方法与等价性论证

论文主线是：保留原生 map lookahead 的代价模型和采样结果，重排独立采样任务的执行，解除组内并行的宽度限制，并在原生 VPR 中验证构建成本、完整布线进程和质量。三维 RR 图提供高成本验证场景；目前没有建立新的三维寻路算法或 GPU 加速贡献。

## 原生计算及可变状态

按原始顺序枚举组 `g=(from_layer, segment, channel)`，每组有有序起点 `s[g,j]`。一次 flood 读取 RR 图和既有代价数据，私有状态包括 expanded 位图、visited 代价数组、优先队列和采样结果表。每次 flood 初始化自己的标签和队列；工作线程之间不共享这些可写状态。原生单次搜索的堆比较、边遍历、代价计算及相对坐标记录不改变。

线程私有工作区可以在同一线程的多个任务之间复用。允许复用的是存储，不能把上一 flood 的标签当下一 flood 的搜索结果，也不能把不同起点压成一个最近来源。此处样本并行与此前修复的路由前驱/包围盒通知状态是两个问题；所有本轮修复版对照均保留相同修复。

## 原序归并为何必要

对固定表单元，原生 `SMALLEST` 规则只在新 delay **严格更小**时更新，因此相同 delay 必须保留原先对应的 congestion。结果可描述为：在原始访问序列中，取 delay 最小且最先出现的条目。

在记录 delay 不含 NaN、单个 flood 的访问序列保持不变的条件下：

1. 每个样本内部取最小且最早的条目，等价于原生该样本对这个单元的贡献。
2. 把各样本代表条目按原始样本顺序，用相同严格比较归并，仍选中全序列中最小且最早的条目。
3. 任务实际完成顺序不影响归并顺序，因此不改变该单元的 delay/congestion。
4. 原有组写入顺序、缺失项插值及切片内 x/y 扫描顺序保持不变，最终 wire map 相同。

这不是无条件交换浮点运算的论证。特殊 NaN 输入、改变 flood 内部堆行为、完成顺序归并或改变插值扫描次序均不在上述证明范围。缺失单元仍按原生规则处理。此前插值重排/compact/bounded 候选不属于本轮 flat 对照。

## 三种实现检验什么

|实现|执行与归并|能检验的因素|
|---|---|---|
|组内 `parallel_for`|逐组启动样本，组内原序归并后进入下一组|每组只有少量样本时的并行宽度限制|
|全局 `parallel_for`|展开全部组/样本，一次并行执行；全局 join 后按原序归并|消除组边界、跨组复用 TLS 后的直接实现|
|有序 pipeline|同一全局任务列表；并行 flood，原序提交；限制在途 token|相对于直接展开，有限在途结果与搜索/归并重叠的组合效果|

全局 `parallel_for` 与 pipeline 使用同一 ELF、同一任务生成代码、同一 flood、同一结果表示、相同组输出顺序。该对照仍不是“只改变调度开销”：样本表生命周期、归并重叠和分配行为会随执行方式改变，结果必须按组合实现解释。

oneTBB 的 `parallel_for`、线程私有存储和有序 pipeline 都是已有原语。当前可讨论的贡献是原生构建流程的依赖分解、等价集成与实证分析；不能把调用库原语写成发明新调度算法。若两种全局实现效果接近，结论应归于解除组边界，而非宣称 pipeline 独有优势。若 flat 更快，也应保留该结果并据此选择实现。

## 并行宽度的简单模型

设每个样本在理想条件下的搜索成本为 `t[g,j]`，组成本 `Wg=Σj t[g,j]`，总成本 `W=Σg Wg`。忽略调度、分配、归并和共享资源竞争时，逐组执行的搜索墙钟至少为 `Σg max(Wg/P, max_j t[g,j])`；完全展开后的对应下界为 `max(W/P, max_gj t[g,j])`。这个比较解释组边界带来的可用并行度损失，不能据此断言某个具体调度器达到下界。

例如10组、每组4个等成本样本，在8/16核上，组内仍需10个四任务批次；理想全局执行分别需5/2.5个等效批次，工作量/并行宽度的渐近比较为2×/4×。由于任务不可再拆分，40个等长任务在16核上实际至少需要3个完整波次，即该离散模型上限为10/3≈3.33×；4×只是忽略尾部离散性的宽度上限。真实任务成本不等、P不等于实际活跃工作区数、后续src/opin及串行归并也存在，必须由原生计时检验。此模型既不等同CPU硬件利用率，也不直接预测完整布线进程加速。

|核数P|组内等长任务波次|全局等长任务波次|全局相对自身1核模型加速|全局相对组内模型加速|
|---:|---:|---:|---:|---:|
|1|40|40|1×|1×|
|2|20|20|2×|1×|
|4|10|10|4×|1×|
|8|10|5|8×|2×|
|16|10|3|13.33×|3.33×|

这一示例解释为什么4核以下收益可能很小甚至被开销抵消，以及为什么40任务的实验不应以16倍作为等长任务的可达目标。已有约12倍的阶段结果与该模型相容，但仅凭相容不能证明任务等长、负载均衡最优或因果完全隔离。小图若只有8个样本，增加到16核不会增加可同时执行的独立样本数。

完整进程还受构建占比限制。在其他工作完全不变的理想模型中，若构建占基线进程时间的比例为 `f`、构建加速为 `s`，则进程加速为 `1/((1-f)+f/s)`。例如假设 `f=10%`、`s=3`，模型仅预测约1.071×整体加速。该数字是示例，不是新增测量。缓存命中移除大部分wire构建后，新增收益理应被摊薄。实际路由轨迹、RR读取、分配/清理和派生表成本仍须实测；不同电路集合的阶段加速与进程加速不能代入同一个公式，更不能互相相乘。

## 存储关系与测量边界

设 `G` 为已分配结果表的组数、`S` 为总样本数、`Sg` 为组内样本数、`P` 为线程预算、`M=LWH` 为一张表的单元数。启用层上的组即使没有找到采样点，也可能已分配结果表，因此G不能简单等同于非空采样组数。各方法另有共同的最终 lookahead 表和 RR 图。

|实现|样本表保留上界|组结果表|搜索工作区|
|---|---:|---:|---|
|组内|当前组 `Sg` 张|当前组 1 张|当前组实际创建的 TLS 数|
|flat|`S` 张|`G` 张|全局实际创建的 TLS 数|
|pipeline|`min(S,2P)` 张|`G` 张|全局实际创建的 TLS 数|

表中的数量是当前实现的对象存储关系，不是 RSS 上界。一个 `Expansion_Cost_Entry` 含 vector 头；有效单元还有条目存储及分配器开销。搜索工作区的队列、TBB 状态和内存分配器缓存也需要计入进程实际占用。不能直接把 TLS 数设成 P，必须记录实际创建数。

本轮诊断在 `MapLookahead::compute` 入口/出口及期间读取 `/proc/self/statm`，目标间隔 2 ms，记录实际采样数量与最大观测间隔。它能观察 RR 加载之后的活跃 RSS，避免误把 `ru_maxrss` 历史峰值当阶段占用；但 statm 本身近似，采样仍可能漏峰，所以只称“阶段内观测峰值”。诊断同时记录搜索标签 vector 容量和表头结构字节，明确排除队列、分配器与单元条目负载。诊断运行不进入正式速度统计。

标签容量仅统计 wire flood 的 expanded/visited 两个数组。src/opin 等后续计算的独立工作区不在这个容量计数内，但它们运行期间的进程RSS仍落在阶段采样范围。因此“阶段RSS”和“wire标签容量”不是同一个测量边界，不能直接相减来推算所有未计入的数据结构大小。

大型二维BNN的诊断提供了这个区分的实际例子：4个非空采样组、每组4个样本，但全局实现分配了6张组表。8核时S=16、2P=16，所以flat与pipeline的样本表上界同为16；不能套用三维40样本案例中16对40的表数差。二维观测RSS峰值两者仅差约0.57MiB，仍不足以建立稳定内存节省主张。

## 分层验证与主张

代码论证、已有合成语义检查、原生 wire map 字节比较和完整合法路由互相补充。序列化 wire map 不包含全部派生 src/opin 状态，不能把字节比较扩大成所有内部状态的独立验证。最终路由也不必逐字节相同；使用原生 FULL 检查、原版独立 FULL/STA 和预先冻结的 CPD/线长门槛评价质量。

一轮路由的阶段实验即使正常返回 rc2，也只证明构建测量有效；不能计入合法路由成功数或完整进程加速。完整流程主表则只使用合格、完整、独立复核的配对测量。共同缓存后的历史近持平结果、低核数退步、bounded 拒绝和失败布局必须保留。

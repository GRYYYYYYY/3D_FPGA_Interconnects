# VPR–GPU 规模与质量实验，2026-10-25

目标是在真实电路和固定输入下寻找随规模增长出现的加速交叉点，同时报告质量代价。
结果允许为“没有交叉点”或“加速只出现在质量不可接受的结果中”。

## 固定输入与案例

复用相邻工程冻结的干净原 VPR 可执行文件、架构、打包网表、布局和有向 RRG。
新工程只读这些文件，所有新结果写入本项目。资源图、输入文件和参考路由都有 SHA256。
包含原图全部节点和边，不裁剪电路或构造重复网络来放大规模。

| 案例 | 网络数 | 参考 VPR 布线时间 | 用途 |
|---|---:|---:|---|
| ex5p | 679 | 0.53 s | 既有小规模控制 |
| softmax | 11,320 | 2.26 s | Koios 规模序列 |
| clstm_like.large | 31,465 | 12.09 s | Koios 规模序列 |
| reduction_layer | 50,369 | 18.67 s | Koios 规模序列 |
| gemm_layer | 206,155 | 67.72 s | Koios 规模序列 |
| elliptic | 2,849 | 159.85 s | 高拥塞压力，单独分析 |

参考时间仅用于选取案例，不充当本轮加速比的分母。Koios 四个案例使用相同架构描述，
自动生成的器件尺寸随电路变化；每个案例内 VPR/GPU 的布局、宽度、图和容量完全一致。
ex5p 是人为平衡分层压力布局；elliptic 的长耗时主要来自 194 轮拥塞协商，不能作为规模递增证据。

## 方法与计时

在同一 H100 工作节点顺序执行，VPR 使用一个 CPU worker，GPU 路由器使用一个主机线程。
每轮轮换执行顺序。路由最大 200 轮，VPR 关闭失败预测器，拥塞模式阈值 0.25；
每次路由进程限时 600 秒。失败、超时和 FULL 失败均保留，不纳入有效速度/质量比。

每个案例、每种方法先运行一次；完整通过后再运行两次确认。首轮失败时后两轮明确标记为
未尝试，不能将它们计为成功或冒充三次重复。成功率按实际尝试次数报告，另列未尝试次数。
三次相同固定布局实验用于测量性能波动和路径确定性，不能代替不同布局种子的泛化验证。

三种方法：

- `vpr`：冻结原版 timing-driven VPR，路由、FULL 检查和 STA。
- `unit`：已有跳数/拥塞代价、增量多源构树、活跃前沿 CUDA。
- `delay_proxy`：每条边代价为 `1 + round(switch Tdel / 1 ps)`，采用保留源点距离的最短路树。
  所有终端共享同一拥塞快照的源点距离，取回路径时只添加尚未存在的前缀后分支。
  这是时序代理与构树策略的组合对照，不声称分离了两者的贡献，也没有 STA 关键度反馈。

CPU 与 GPU 的源点构树用随机图多终端最短路 oracle 验证。已有 `unit` 默认路径保持不变。
源点构树暂不支持 portal 剪枝或旧 `cuda_dense`，避免不同快照/不同等价路径规则混合。

同时记录三层耗时：

1. 路由进程：初始化、加载图、GPU 上下文/传输、路由及输出；GPU 的该时间不包含回验。
2. 完整固定端点流程：GPU 路由进程、独立审计、trace 导出、原 VPR FULL/STA；
   原 VPR 对照是相同固定布局下路由至 FULL/STA 的完整进程。交叉点以此层为主。
3. 内部路由与搜索：原 VPR 日志 timer；GPU `routing_seconds` 和同步主机墙钟搜索 timer。
   GPU 内部路由 timer 不包含构建 GPU 上下文和初始图上传；搜索 timer 也不是纯 kernel 时间。

图转换、端点准备及输入哈希验证是离线准备，独立记录，不隐藏到“免费开销”中。
输入在计时前完成哈希验证，因此本轮不宣称冷文件缓存性能；每次测量都启动独立路由进程。
GPU H2D 传输计数包含最初的静态图上传、状态快照和新增根节点；D2H 包含前沿计数和路径。
初始图上传不在内部路由 timer 内，但包含于完整进程时间。
本实验从参考 VPR route 提取端点但不读取中间路径作为路由输入。
因此完整时间的严格范围是**固定端点的路由至 FULL/STA**，尚不是独立替代 VPR 的完整 CAD 流程。
要声称首次使用新架构时的完整工具加速，还需消除参考路由端点依赖并计入转换成本。

## 质量与成功条件

完整电路必须全部连通、容量零超用，并通过原 VPR FULL。CPD 与线长使用原 VPR 同一口径。
对每次配对计算 CPD 和线长相对变化，以及完整流程加速比。
5%、10%、20% 三档同时限制 CPD 与线长，作为敏感性分析，不预设用户接受哪档。
原型投影审计通过但原 VPR 不通过的结果不能宣称合法完成。

## 运行入口

`scripts/prepare_scaling.py` 生成投影与冻结案例；`scripts/run_scaling.py` 在 GPU 节点运行全部测量。
`data/vpr_runtime_20261025/runtime.json` 锁定 Tcl/TBB 等运行库，启动时先在实际 GPU 镜像执行 VPR smoke。
任务使用隔离源码快照，保留本机验证、平台回执、设备信息、每次命令、日志、计时和失败记录。

运行预算补充：首次作业上限两小时。若平台时限使实验组不完整，保留全部原始记录，
对未完成案例另开同规格作业重跑完整配对组；同一案例的主要三轮比较不跨工作节点拼接。
报告必须指出哪些案例由补跑获得，原始失败/超时尝试不能删除。

时序对照限制：`delay_proxy` 沿用默认拥塞参数，改变了边权的数值尺度，尚未校准时序与拥塞
项的相对权重；所有网络采用相同源点构树策略，没有按关键度分配资源。
因此它仅检验这一具体配置，不能代表时序驱动 GPU 路由的最佳质量，也不能从其失败推断
时序驱动方法本身不可行。

# CPU 主线的证据与实验边界

本轮用户已授权执行 CPU 主线评估。研究问题是：保留合法性和布线质量，CPU 改进能否稳定减少原生 VPR 路由流程时间，收益来自哪一步，以及公平提供缓存后还剩多少收益。CPU 本身有价值，不以 GPU 必须获胜作为门槛；是否足以形成论文，需要方法区别于已有工作并有充分验证。

## 冻结比较

主计划为 `results/native_cpu_paper_20261031/plan.json`。原版使用锁定的历史二进制；独立 CPU 快照从同一提交 `0b912334fdd83bb754b302146ac0d1ec9edc9a0e` 导出，仅加入两处搜索框更新通知修复和可关闭的 lookahead 采样并行。没有 GPU 接管钩子。修复版和优化版使用同一个二进制，差异只有 `VPR_HYBRID_LOOKAHEAD_PARALLEL=1`。

| 比较 | 回答的问题 |
| --- | --- |
| 原版 vs 修复版 | 正确性修复对稳定性、质量和性能的影响 |
| 修复版 vs 优化版 | 独立于修复的 CPU 优化收益，主归因对照 |
| 三者同样重建 map | 每次需要生成 lookahead 的实际路由流程收益 |
| 三者读取同一 map | 资源图不变、可复用缓存时的收益 |
| 修复版 `parallel_decomp` | 原版已有更积极并行能力是否改变结论 |
| 二维 `compressed_map` | 更便宜的既有 lookahead 是否有竞争力 |
| 1/2/4/8 物理核 | CPU 扩展性、单核额外开销和并行上限 |

现有六电路各三次运行，固定网表、布局、资源图和 seed。重复是运行时间重复，不是三个布局种子。GEMM 三次重复分配到不同物理核组，但每一组内部所有对照使用相同核集合；禁止跨组直接配对。所有 VPR 线程继承亲和性，每五秒采样审计。主矩阵最多同时使用24个物理核；架构准备使用另外4核，宿主仍有其他任务，不声称资源独占。最终论文确认需要隔离的重复测量。

## 时间与合法性

主指标是 VPR 进程墙钟时间：包含已打包网表与固定布局的加载/检查、RRG XML 读取、lookahead、路由、VPR 自带 FULL 与 STA；不重新执行打包和布局算法。因此不能称为完整 FPGA 编译加速。独立原版回读属于额外验证，单列 workflow 时间，不把它混入算法路由时间。逐项保存 lookahead、RRG 读取、Routing、迭代数、CPD、线长和内存记录。

所有输入在计时前同样顺序预读，`rebuild` 仅表示重建 lookahead，不表示磁盘冷缓存。每个 case 由原版串行采样与优化版并行采样分别生成 map，逐字节一致后，所有 reuse 对照读取同一个原版 map。缓存资格检查限一轮路由；VPR 返回2表示未收敛，缓存写出成功仍可完成资格检查，但该过程绝不进入性能或质量样本。

正式成功样本须完整收敛、零超用、原生 FULL/STA 和独立原版 FULL/STA 均通过，CPD/线长在两次检查中一致，路由文件回读前后 SHA 不变。相对配对基线，CPD 与线长退化各不超过5%方可进入合格加速汇总。失败、超时和不收敛保留；不得用失败程序的短耗时计算加速。

报告每次配对速度比、三次中位数及范围，再对电路级结果取几何平均，并报告最差电路。小规模运行次数不能支持高置信度总体结论。算法质量需后续多布局种子与更多独立电路验证。

## 已知边界和文献

锁定源码的 `router_lookahead_compressed_map.cpp:516` 明确断言只支持一层；三维 ex5p 预检返回 SIGABRT，失败保留。不能把不兼容算成击败强基线。二维 Hecate 对照会单独验证该配置。原生架构扩展使用官方 Hecate XML，由 VPR 生成资源图；二维重新打包布局，三维宽度变更保留原固定布局。原有图与新生成图不能跨图计算算法收益。

[VPR 官方选项](https://docs.verilogtorouting.org/en/latest/vpr/command_line_usage/) 已提供 `parallel`、`parallel_decomp` 和 lookahead 读写，因此简单启用线程或只给候选提供缓存不能视为创新。[FPT 2024 MultiQueue 论文](https://www.eecg.utoronto.ca/~mcj/papers/2024.mqrouter.fpt.pdf) 提出连接内并行搜索，并讨论 Dijkstra 在 lookahead 预计算中的成本。我们的多起点采样并行与它的单次搜索并行不同，但“并行加速 lookahead”这一方向本身不足以证明新颖性。不得将不同机器、线程数、启发式或时间边界下的论文速度比直接与本实验比较。

若共同缓存后收益消失，应把贡献界定为架构探索或新资源图的预计算优化。若需要提出路由算法论文，则仍需针对实际路由阶段设计并验证方法。三维数据集上的通用并行实现也不自动构成三维专属算法贡献。

## 已完成的本轮结果

全部九个计划已终态：实际290项，284项合法且独立FULL/STA通过，6项失败/超时保留，4项按原版失败门槛跳过。503个冻结文件、30组缓存资格和88个计时map通过审计；6项比较/计时测试通过。完整结果见 [实验报告](../results/native_cpu_paper_20261031/report.md)、[验收](../results/native_cpu_paper_20261031/acceptance.json) 和 [图表](../results/native_cpu_paper_20261031/figures/cpu_study.pdf)。

同四物理核、修复控制到组内采样并行，六电路重建lookahead的配对速度比几何平均为1.351×，共同缓存为0.995×。GEMM对原版parallel三次中位1.503×；lookahead中位163.46→42.60秒，而Routing中位36.52→37.06秒。因此收益应归于预计算，不能称为路由搜索加速。

CLSTM修复版parallel相对原版CPD退化17.17%，不能计作质量合格获胜；独立的decomp确认得到CPD6.42742ns，相对原版decomp6.53755ns改善1.685%，组内采样三次中位1.320×。原版elliptic并行崩溃，无有效原版并行速度比；修复与采样优化在1/2/4/8核均复现10.841ns、97461线长和160轮。

新全局pipeline四核GEMM中位0.937×，八核lookahead虽为1.924×，进程仅1.010×且范围跨过1。它保持实验选项，不替代现有组内采样；同二进制单次归因提示重构后旧调度也有额外未覆盖成本，具体根因尚未确定。

本轮支持以CPU lookahead预计算为研究主线，未证明通用路由阶段加速、任意三维架构推广或论文新颖性。2026-11-01 已完成后续[查新与方法可行性分析](native_lookahead_novelty_analysis.md)：明确已有论文和上游问题的贡献归属，独立验证插值切片之间没有数值依赖，并量化历史分项及计时残差。下一步按该分析的实验规格先定位成本，再隔离验证插值重排、连续结果表和有界调度；扩大基准不能替代方法差异。所有缓存公平提供，GPU保留后续扩展，不设GPU独立获胜为论文门槛。

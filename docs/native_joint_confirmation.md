# 原生联合方案四核确认实验

本轮执行预先声明的 [实验矩阵](../results/native_joint_confirmation_20261030/plan.json)，不修改路由算法或接管参数。目标与公平比较口径以 [联合优化目标](native_joint_objective.md) 为准。运行入口是 `scripts/run_native_joint_confirmation.py`，结果分析入口是 `scripts/report_native_joint.py`。

## 对照与资源

| 变体 | 实际执行 | 回答的问题 |
| --- | --- | --- |
| original_parallel | 锁定原版 VPR，parallel，4 workers | 相同 CPU 核预算下的主基线 |
| native_parallel | 修改版 VPR，关闭 GPU 与所有权保护 | 集成钩子的影响；尚不是独立的新 CPU 算法 |
| guard | 修改版 VPR，启用与 batch 相同的所有权保护，关闭 GPU | 保护与执行顺序的影响 |
| batch | 4 路由 workers 与 GPU 服务线程，共享同一四核亲和性 | 联合方案相对原版并行的完整收益 |

每组限制在同样四个不同物理核上，每核仅使用一个逻辑 CPU。GPU 服务及驱动线程也继承这个亲和性。每五秒检查一次所有 VPR 线程；记录观察到的最大线程数、越界、CPU user/system 时间和 cgroup 状态。线程数可能大于四，但可运行 CPU 核集合保持四个。采样不能排除两次采样间的瞬态变化，也不声称这些核独占于本作业。

GEMM 做三轮，每轮旋转 A/B/C/D 的执行顺序。elliptic 先各做一次；若四组均合法且 CPD/线长各在原版 +5% 内，再自动补两轮。失败保留，并输出超用节点报告。并行路由可能因调度产生不同路径，因此使用独立 FULL/STA、合法性与质量约束，而非强制不同并行执行的路径字节一致。

## 计时与验证

每次使用新 VPR 进程。对所有变体，在计时前顺序读取同一组输入，单独记录预读字节数与时间；不刷新系统全局缓存。这是同等输入预热条件下的测量，不是文件系统冷缓存实验。每次仍重新解析图、构建 lookahead、执行路由及进程内 FULL/STA；batch 初始化、图上传、服务线程和提交开销都在计时内。

`native_process_seconds` 是 VPR 子进程墙钟时间。`workflow_seconds` 还包括准备该次工作目录、路由文件哈希和锁定原版 VPR 的独立 FULL/STA 回读。编译、输入绑定验证与预读分别记录，不混入前述时间。独立复核属于实验验证成本；两种时间分别报告，不把复核加速冒充路由进程加速。

正式确认关闭 CUDA events、状态快照和原生 CPU 配对重放。保留轻量查询记录、实际 GPU 提交与错误计数。分项计时采用 VPR 自带日志；GPU 内部阶段归因使用此前独立诊断结果，不能从关闭 events 后的运行伪造 kernel 时间。

比较仅使用同一作业内相同电路与重复编号的原版并行基线。质量门槛为合法零超用、进程内及独立 FULL/STA 通过、CPD/线长各不超过原版 +5%。batch 还必须实际初始化 GPU 并提交结果，且没有 GPU error/fallback。CPU/guard 对照用于归因和实际配置选择，不要求 batch 必须胜过它们才能认可相对原版的联合收益。

三轮均合格且进程及 workflow 都更快，才标记为本电路的正向候选；不把三个样本称为统计显著性证明。所有失败、运行顺序、输入预读、CPU 审计、分项日志、质量及路由哈希均保留。

## 冻结与归档

提交前冻结源码、CPU 二进制、输入引用、运行库与脚本并绑定 SHA256；GPU 节点重新编译 CUDA 库并先执行回放 oracle。最终归档核对冻结文件、实际 CUDA 库及路由文件哈希，并提取小型证据供分析。最终平台状态、归档校验与实验结果分别检查，不能仅凭 live 日志认为作业完整结束。

第一项作业因共享项目存储配额导致日志镜像失败而终止，没有完整可用测量。后续脚本将镜像写入错误与求解过程隔离，并预留归档空间。失败回执和存储迁移记录保留在本轮结果目录；迁移仅针对已结束的生成归档与既存崩溃转储，并按完整 SHA256 验证。
